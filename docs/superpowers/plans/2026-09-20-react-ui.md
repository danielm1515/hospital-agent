# Sub-project 6 (React UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the §1 UI Component: a Hebrew/RTL React app with a patient area and a staff area, on top of sub-project 5's `/api`, styled after the user's design (`design/ramon-ui/`).

**Architecture:**
- A Vite + React 18 + TypeScript SPA lives in `frontend/`. It has one API client (bearer token kept in `sessionStorage`), React Router routes per area, and presentational components that reproduce `design/ramon-ui/components.html` on top of the imported `tokens.css`.
- A `frontend` service in docker compose runs the Vite dev server on 127.0.0.1:5173 and proxies `/api` to the backend.

**Tech Stack:**
- Node 22, Vite 5, React 18, TypeScript 5, react-router-dom 6.
- Vitest, @testing-library/react, @testing-library/user-event and jsdom.
- No UI component library.

**Spec:**
- Design: `docs/superpowers/specs/2026-09-20-react-ui-design.md`.
- API contract: `docs/api.md` (written by sub-project 5). It is the only source for request and response shapes.
- Design reference: `design/ramon-ui/*.html`, `tokens.css` and `DESIGN-NOTES.md`.
- Binding spec: `docs/spec/` §1, §12.3, D24.

## Global Constraints

- **Hebrew/RTL:** the `<html lang="he" dir="rtl">`, and CSS uses logical properties only (`margin-inline-start`, `inset-inline-*`, …), as the design does.
- **Tokens:** import `design/ramon-ui/tokens.css` unchanged. Copy it to `frontend/src/styles/tokens.css`, and a test must check it is byte-identical to the design file. Colors, spacing, radii and type come only from its variables and classes.
- **Fonts:** IBM Plex Sans Hebrew and IBM Plex Mono via the design's Google Fonts `<link>`s in `index.html`.
- **Copy:** reuse the design's Hebrew text verbatim where a screen matches a design page. New text is concise Hebrew.
- **API use:**
  - The client never sends `reviewer_id`, `reviewer_role` or `patient_id`; identity comes from the token.
  - The patient UI never shows escalation kinds, reasons or Audit (§12.3).
  - The staff decision always sends the `shown_context_ref` of the context on screen.
- **Tests and build:** `npm test` (Vitest) passes; `npm run build` (`tsc -b && vite build`) passes with no type errors.
- **Where commands run:** run npm on the host inside `frontend/`; Node 22 is installed.
- **Docker:** the compose `frontend` service must work with `docker compose up frontend`. Never run `up`, `down` or `-v` against the user's stack from a worktree; the controller verifies the stack after the merge.
- **Line endings:** LF.
- **Commits:** every commit message ends with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- **Secrets:** never read or print `.env` or any key.

### Task 1: Scaffold, design-system components, API client, routing shell

**Files (create):**
- **Project setup:** `frontend/` with `package.json`, `package-lock.json`, `tsconfig*.json`, `vite.config.ts` and `index.html`.
- **Styles:** `src/styles/tokens.css` (a copy of the design file), and `src/styles/app.css` (layout and component CSS, using logical properties and only token variables).
- **Components:** `src/components/{Logo,Button,TextField,Alert,StatusPill,ThemeToggle,AuthLayout,AppShell}.tsx`.
- **API client:** `src/api/client.ts` and `src/api/types.ts`.
- **App:** `src/auth/AuthContext.tsx`, `src/App.tsx` (routes) and `src/main.tsx`.
- **Tests:** `src/test/setup.ts`, and a test file next to each component and next to the client.
- **Container:** `frontend/Dockerfile` (node:22-alpine, `npm ci`, `npm run dev -- --host 0.0.0.0`) and `frontend/.dockerignore`.
- **Modify:** `docker-compose.yml` to add the `frontend` service:
  - build `./frontend`;
  - ports `127.0.0.1:5173:5173`;
  - env `VITE_API_PROXY_TARGET=http://backend:8000`;
  - `depends_on` backend;
  - volume `./frontend/src:/app/src`.

**Scripts:** `dev`, `build` (`tsc -b && vite build`), `test` (`vitest run`) and `preview`. In `vite.config.ts`, `server.proxy['/api'] = { target: process.env.VITE_API_PROXY_TARGET ?? 'http://127.0.0.1:8000', changeOrigin: true }`.

**Components:** reproduce the classes, variants and states of `design/ramon-ui/components.html` and `DESIGN-NOTES.md` §3.
- `Logo`: variants `full`, `compact` and `onbrand`. Use the inline SVG from the design.
- `Button`: variants `primary`, `secondary`, `quiet` and `danger`, plus `busy` (spinner and `aria-busy`), `block` and `disabled`.
- `TextField`: `label`, an optional `prefix`, `hint`, `error` (sets `aria-invalid` and `aria-describedby`), `disabled`. It supports `multiline` (a textarea) and a character counter.
- `Alert`: variants `info`, `warn`, `error` and `ok`; `role="status"`, or `role="alert"` for `error`.
- `StatusPill`: one per patient status, with Hebrew labels:
  - `received`: התקבלה
  - `in_progress`: בטיפול
  - `needs_document`: ממתינה למסמך
  - `in_review`: אצל צוות
  - `completed`: הושלמה
  - `closed`: נסגרה

  It also has a staff variant that shows a raw State in mono `.state` style.
- `ThemeToggle`: follows the design's logic and persists the choice in `localStorage`, wrapped in try/catch.
- `AuthLayout`: the `.screen`, `.form-pane` and side-pane split, stacking below 900px.
- `AppShell`: a top bar (compact Logo, the user's display name, a logout `quiet` button, ThemeToggle) with the page body below.

**API client** (`client.ts`):
- `login(user_id, password)` and `me()`.
- **Patient:** `createRequest(text)`, `listRequests()`, `getRequest(id)`, `uploadDocument(id, {document_id, format, content})`.
- **Staff:** `listCases(state?)`, `getCase(id)`, `getAudit(id)`, `listReviews()`, `getContext(id)`, `decide(id, body)`, `tombstone(id, entryId)`.
- **Errors:** on a non-2xx response it throws `ApiError {status, detail}`. On 401 it also clears the token and calls an `onUnauthorized` hook.
- **Types:** take every type in `types.ts` from `docs/api.md`.

**Routes:**
- `/`: redirects by role, or to `/login`.
- `/login`: patient login.
- `/staff/login`: staff login.
- `/patient/*`: patients only.
- `/staff/*`: staff only.

In this task the patient and staff pages are placeholder components; Tasks 2 and 3 fill them in.

### Task 2: Patient area

**Files:**
- `src/pages/patient/{PatientLogin,MyRequests,NewRequest,RequestDetail}.tsx`, with tests next to each.
- Patient-specific styles go in `app.css`.

**Screens** (see design §3–4):
- `PatientLogin`:
  - uses `AuthLayout`;
  - reuses the brand pane from `patient-login.html`, including the SVG pattern, the eyebrow, the heading, the text and the facts, all verbatim;
  - the form keeps the step-indicator styling, but has two fields, "מזהה מטופל" and "סיסמה", plus a "משתמשי דמו" row of `quiet` buttons (P-10041, P-20000, P-30000) that fill in the id;
  - shows an `Alert` error for `invalid_credentials`.
- `MyRequests`:
  - one card per request, with the text truncated to 120 characters, a `StatusPill` and the date;
  - a "פנייה חדשה" primary button;
  - polls every 3 s while any request is `received` or `in_progress`;
  - an empty state.
- `NewRequest`:
  - a multiline `TextField` (maximum 2000 characters, with a counter);
  - Submit shows `busy` and then navigates to the detail page.
- `RequestDetail`: a status timeline plus content by status.
  - **`needs_document` (D24):**
    - a warn `Alert` built from template `missing-document-v1`: "כדי להשלים את ההכנה לתור חסרים המסמכים הבאים:" followed by the list of `missing_document_ids`;
    - an upload form for each missing id: a file input that reads text via `File.text()`, or a textarea to paste into, plus a format select (pdf, jpg, png);
    - sending shows `busy`, and then the page reloads its data.
  - **`completed`:** an ok `Alert` titled "ההודעה שנשלחה אליך" containing `message`.
  - **`in_review`:** an info `Alert` reading "הפנייה הועברה לבדיקת צוות. מידע רפואי אינו נמסר באופן אוטומטי."
  - **`closed`:** a neutral text reading "הפנייה נסגרה."
  - **Polling:** every 3 s while the status is `received` or `in_progress`.
  - **Never shown:** escalation or Audit data.

### Task 3: Staff area

**Files:**
- `src/pages/staff/{StaffLogin,ReviewQueue,ReviewCase,CaseMonitor}.tsx`, with tests next to each.
- Staff styles go in `app.css`: tables, a timeline, and a three-column layout.

**Screens** (see design §3, §5):
- `StaffLogin`:
  - uses `AuthLayout`, with the side pane from `admin-login.html` verbatim: "איך מפיקים את הקוד" becomes a short "משתמשי דמו" note, while the `.scope` list "מה מותר מהמסך הזה" and the audit line are kept verbatim;
  - the form has the "STAFF ACCESS" badge, the H1 "כניסת צוות רפואי", and the id and password fields;
  - it has demo buttons for `coordinator_nurse` and `admin_coordinator`.
- `ReviewQueue`:
  - a table of case id (mono), patient, escalation kind (a Hebrew label, with the code in mono below it), from-state, reasons, and last updated;
  - polls every 5 s;
  - clicking a row navigates to `/staff/cases/:id`;
  - an empty state reading "אין פניות הממתינות להכרעה".
- `ReviewCase`: three columns.
  - **Data Log content:** grouped by kind (request, documents, instructions, outgoing message). Each item has a "מחיקה לפי בקשת מטופל" `danger` button behind a confirm dialog, which tombstones it and then reloads the context.
  - **Audit timeline:** each row shows `record_type`, the event, `state_before` → `state_after` in mono, the time, and `policy_reasons`.
  - **Decision form:**
    - buttons only for `allowed_decisions` (approve: "אישור והמשך", resolve: "סגירת הפנייה", reject: "דחייה");
    - a required reason textarea;
    - the extra fields from `required_fields`: `verified_identity_ref` as text, `patient_deadline` as a `datetime-local` converted to an ISO string with the offset;
    - it sends `shown_context_ref` from the loaded context.
  - **Decision results:**
    - 409 `context_changed`: an error `Alert` with a "רענון הקשר" button;
    - any other 409: its `detail`;
    - success: navigate back to the queue with an ok `Alert`.
- `CaseMonitor`:
  - a state filter select and a cases table (id, patient, State as a mono pill, intent, safety, updated);
  - a row expands to show the case detail and the Audit.

The staff shell nav has "תור הסלמות" and "כל הפניות".

  - the decision posts `shown_context_ref` and the reason;
