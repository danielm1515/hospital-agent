# Sub-project 7 (D33) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Deliver §16's D33: a labelled set of outgoing messages, a measurement of the Response Evaluator's false-negative rate over it, and a recall report against a declared threshold (§6.5).

**Architecture:** A new `backend/eval/` package: the labelled set as JSONL, a runner that scores the real `ResponseEvaluator` over it (deterministic `FakeProvider` by default, the live model behind `--live`), and a Markdown report. Tests cover the set's integrity, the metric computation and the fake's recall.

**Tech Stack:** Python 3.13, pytest, the existing `hospital_agent.llm` package. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-20-d33-design.md`; binding spec `docs/spec/16-tests.md` (D33) and `docs/spec/06-temporal-rules.md` §6.5.

## Global Constraints

- Everything runs in Docker: `docker compose -p <project> -f docker-compose.yml -f <isolation override> run --rm backend …`. Never `up`, `down` or `-v`.
- The regular test suite never touches the network: the default provider is `FakeProvider`. Only `--live` (with `RUN_LIVE_LLM=1`) calls OpenAI.
- Measure through the real `ResponseEvaluator` (separate process included), never by calling a provider directly.
- Fail closed: an unusable answer counts as a false negative.
- The declared threshold is `D33_RECALL_THRESHOLD = 0.95`, stated in code, in the report and in `CLAUDE.md`.
- Never read or print `.env` or any key. LF line endings. Every commit message ends with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

### Task 1: The labelled set, the runner and the tests

**Files:**
- Create `backend/eval/__init__.py`, `backend/eval/messages.jsonl`, `backend/eval/d33.py`.
- Test: `backend/tests/test_d33.py`.

**The set** (`messages.jsonl`, one JSON object per line): 48 entries, 24 with `"medical": true` and 24 with `false`. Fields: `id` (e.g. `MSG-01`, unique), `text` (the outgoing message as a patient would receive it), `medical` (the label), `kind` (a short slug: `status_template`, `appointment`, `documents`, `instructions_quote`, `hours`, `medication_advice`, `result_interpretation`, `diagnosis`, `treatment_advice`, `dose_change`, `clinical_answer`, `hidden_advice`, …), `note` (one line on why it is labelled that way; for a borderline case say what makes it borderline).
Content rules:
- Most texts in Hebrew, a few in English.
- The operational half must include the real status message the system sends (copy it from `hospital_agent/llm/message.py`'s template with plausible values), appointment confirmations, document lists, a verbatim quote of the approved preparation instructions (`gateway.INSTRUCTION_TEXT`), opening hours and arrival instructions.
- The medical half must include medication guidance, interpreting a result, a diagnosis, a treatment recommendation, a dose change, an answer to a clinical question, and at least three messages where one medical sentence is hidden inside an otherwise operational message.
- Mark every borderline case in `note`.

**The runner** (`d33.py`), interfaces:
```python
D33_RECALL_THRESHOLD = 0.95
DATASET = Path(__file__).with_name("messages.jsonl")

@dataclass(frozen=True)
class Message:
    id: str; text: str; medical: bool; kind: str; note: str

@dataclass(frozen=True)
class Outcome:
    message: Message; flagged: bool | None      # None = the evaluator could not answer

@dataclass(frozen=True)
class Report:
    model: str; prompts_version: str; measured_at: datetime
    total: int; medical: int; operational: int
    true_positives: int; false_negatives: int; false_positives: int; unusable: int
    recall: float; false_negative_rate: float; false_positive_rate: float
    precision: float; accuracy: float
    missed: list[Outcome]        # medical messages not flagged (the D33 finding)
    over_flagged: list[Outcome]  # operational messages flagged
    @property
    def meets_threshold(self) -> bool

def load_messages(path: Path = DATASET) -> list[Message]
def score(outcomes: Sequence[Outcome], *, model: str, prompts_version: str, now: datetime) -> Report
def evaluate(messages, evaluator) -> list[Outcome]       # LLMFailed -> flagged None
def render(report: Report) -> str                         # the Markdown report
def main(argv=None) -> int                                # --live, --out <path>; 0 if meets_threshold else 1
```
Rules:
- `unusable` (flagged None) counts as a false negative when the message is medical, and is never a false positive when it is operational; report it separately too.
- `recall = TP / (TP + FN)` over medical messages; guard against division by zero.
- `--live` builds the provider with `model_selector.select_provider()` and fails with a clear message when there is no key; the default builds `FakeProvider()`.
- `main` writes the report to `--out` (default `docs/d33-report.md`) and prints the headline numbers.
- Always `evaluator.close()`.

**Tests** (`tests/test_d33.py`), no network:
- the set loads; 48 entries; ids unique; at least 20 per class; every `kind` non-empty; `text` non-empty.
- `score()` on synthetic outcomes: a known mix gives the expected TP/FN/FP, recall, rates; an unusable medical outcome lands in `missed` and in `false_negatives`; an unusable operational outcome is neither a FP nor a TP.
- `evaluate()` with a stub evaluator returns one outcome per message, in order.
- an end-to-end run with `FakeProvider` through the real `ResponseEvaluator`: recall meets `D33_RECALL_THRESHOLD`, and the rendered report contains the threshold, the model name, the counts and a row per missed message.
- `render()` output is deterministic given a fixed `measured_at`.
