### Task 1 (document-service): report the usage of its LLM call

- `app/classifier.py`: `_call()` reads `response.usage` (`prompt_tokens`, `prompt_tokens_details.cached_tokens`,
  `completion_tokens`; missing/malformed → `None`). `classify()` / `classify_images()` return it with their result
  (or the result object gains a `usage` attribute - follow the file's existing shape); a `ClassifierFailed` for an
  answer that arrived (unparsable) carries its usage. `FakeClassifier` returns deterministic usage.
- `app/intake.py` / `app/main.py`: every 201 answer carries `llm_usage` - `{call: "classify"|"vision", model,
  input_tokens, cached_input_tokens, output_tokens}` when a call was made, `null` when none (duplicate, early
  rejection). The 503 `classifier_unavailable` body is unchanged. No log line gains a count of text.
- README: the new field. Tests: text and vision uploads, a duplicate (null), an early rejection (null), an
  unparsable answer's usage, a missing `usage` on the response (null counts), the answer's key set.

### Task 2 (hospital-agent backend): capture, attribute, price, store

- `llm/usage.py`: `LLMUsage` (frozen; three non-negative ints, `cached_input_tokens` ≤ `input_tokens`),
  `usage_from_response(response)` (defensive; `None` on anything odd), `usage_scope(case_id, recorder)` (a
  contextvar), `report(call, model, outcome, usage)` (no-op without a scope).
- `llm/provider.py`: `OpenAIProvider.complete_with_usage()`; `complete()` delegates. `LLMUnusable(reason, retryable,
  usage=None)` - the usage of a rejected answer. `ask()` uses `complete_with_usage` when the provider has it, and
  reports each attempt (`ok` or the reason) through `usage.report` beside `telemetry.record` (whose signature stays).
- `llm/classifier.py`: submit through `contextvars.copy_context().run`.
- `llm/evaluator.py`: `_evaluate_once` returns `(flag, usage)`; the parent reports ok/failed attempts with usage.
- `llm/pricing.py` (design D3): table, env override for the configured model, `cost(model, usage) -> (price_in,
  price_out, cost) | (None, None, None)`.
- Migration `0008_llm_usage.py` + `db.py` mirror (design D4), grants `SELECT, INSERT` to `hospital_app`; add
  `llm_usage` to the TRUNCATE lists (`tests/conftest.py`, `obs/golden.py`) before `cases`, and to
  `tests/test_patients.py` `OTHER_TABLES`; a test that `UPDATE`/`DELETE` are denied (the `audit_log` pattern).
- `llm_costs.py` (repository side): `UsageRecorder(engine)` - `record(case_id, source, call, model, outcome,
  usage)` prices and inserts in its own `engine.begin()`; any exception → WARNING `llm_usage_write_failed` (code
  only), never raised.
- Orchestrator: `run_case` wraps its steps in `usage_scope(case_id, recorder)` (the recorder built in `wiring` /
  `api/app.py` from the same engine). Rule: **one row per attempt that reached the provider**, ok or failed;
  a provider with no usage (FakeProvider, model `fake`) writes a row with NULL tokens and NULL cost. Golden counts
  audit rows only, so it stays 35/4/54.
- Tests: usage parsing (full, missing, malformed, cached > input rejected), pricing (known, override, bad
  override, unknown model → None, rounding), ask() reports ok and failed attempts with their usage, the
  Classifier's two threads keep the scope, the Evaluator's usage crosses the process (ok and rejected), the
  recorder never raises, append-only grants, a golden run still 35/4/54, no text in log lines.

### Task 3 (hospital-agent backend): document usage, API, metrics

- Tests: aggregation (priced, unpriced, no usage, several sources), the page query with and without usage, the
  range errors, roles (patient 403), `shown_context_ref` unchanged by usage rows, metrics snapshot.
