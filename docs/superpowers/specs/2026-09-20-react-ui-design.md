# תת־פרויקט 6: React UI — מסמך Design

**תאריך:** 2026-09-20
**סטטוס:** נכתב במצב אוטונומי (`CLAUDE.md` → *Autonomous mode*). ההחלטות מתועדות בסעיף 7.
**תלוי ב:** תת־פרויקט 5 (ה־`/api` וחוזה ה־API ב־`docs/api.md`).
**מקור אמת:**
- `docs/spec/` §1: "UI Component: מסך מטופל ומסך צוות", ‏D24 ("בקשת מסמך מוצגת") ו־§12.3 (מה מותר להציג).
- העיצוב שהמשתמש סיפק, ב־`design/ramon-ui/`: ‏`tokens.css`, ‏`components.html`, ‏`patient-login.html`, ‏`admin-login.html`, וסיכום שלהם ב־`DESIGN-NOTES.md`.

## 1. היקף

אפליקציית React אחת עם שני אזורים:

- **אזור המטופל:**
  - כניסה;
  - רשימת הפניות שלי;
  - פנייה חדשה;
  - פרטי פנייה, לפי הסטטוס:
    - `needs_document`: בקשת מסמך לפי התבנית, והעלאה (D24);
    - `completed`: ההודעה שנמסרה;
    - `in_review`: הודעה ש"הפנייה אצל צוות".
- **אזור הצוות:**
  - כניסה;
  - תור ההסלמות;
  - פנייה בתור: ההקשר מה־Data Log, ה־trace מה־Audit, וטופס הכרעה;
  - Case Monitor: כל הפניות, עם סינון לפי State.

**מחוץ להיקף:**
- אנגלית: מתג השפה בעיצוב מוצג אבל לא פעיל, כמו בעיצוב עצמו.
- 2FA ו־OTP אמיתיים: ה־IdP מדומה (§18.3).
- ContentApproval.

## 2. טכנולוגיה

- **כלים:** ‏Vite, ‏React 18 ו־TypeScript, ‏React Router 6. אין ספריית UI.
- **עיצוב:** הקומפוננטות נבנות לפי העיצוב. ‏`tokens.css` מיובא פעם אחת, והגופנים IBM Plex Sans Hebrew ו־Mono מ־Google Fonts.
- **תיקייה:** `frontend/`:
  - `src/api/`: לקוח ה־API, הטוקן ב־`sessionStorage`;
  - `src/components/`: ‏Logo, ‏Button, ‏TextField, ‏Alert, ‏StatusPill, ‏AuthLayout, ‏AppShell, ‏ThemeToggle;
  - `src/pages/patient/*` ו־`src/pages/staff/*`.
- **הרצה:** ‏Docker Compose מקבל שירות `frontend` (‏`node:22-alpine`), שמריץ `npm ci && npm run dev -- --host` על פורט 5173 (`127.0.0.1:5173`). ‏Vite מפנה (proxy) את `/api` ל־`http://backend:8000`, כך שאין צורך ב־CORS בדפדפן, אבל ה־CORS של תת־פרויקט 5 נשאר.
- **בדיקות:**
  - ‏Vitest ו־Testing Library לקומפוננטות, לחוזה הלקוח (עם fetch מדומה) ולכל מסך מרכזי;
  - `npm run build`: ‏`tsc -b` ואחריו `vite build`, בלי שגיאות;
  - בסוף, מעבר ויזואלי ידני בדפדפן על שלושת התרחישים.

## 3. כניסה

- **ההתאמה לעיצוב:** מסכי הכניסה בנויים לפי `patient-login.html` ו־`admin-login.html`:
  - אותו AuthLayout, אותה לוח מותג לצד הטופס, ואותם טקסטים.
  - שדה הטלפון וה־OTP מוחלפים ב"מזהה" ו"סיסמה", כי ה־IdP מדומה (§18.3).
  - מתחת לטופס מופיע "משתמשי דמו": כפתורים שממלאים את המזהה (`P-10041`, `P-20000`, `P-30000` / `coordinator_nurse`, `admin_coordinator`) ומציגים את סיסמת הדמו.
- **ניתוב אחרי כניסה:** מטופל מגיע ל־`/patient`, צוות מגיע ל־`/staff`.
- **טוקן:** יציאה מוחקת אותו. תשובת 401 מחזירה למסך הכניסה.

## 4. מסכי המטופל

- **`/patient`, "הפניות שלי":**
  - כרטיס לכל פנייה: הטקסט המקוצר, ‏StatusPill ותאריך.
  - כפתור "פנייה חדשה".
  - ריענון אוטומטי כל 3 שניות, כל עוד יש פנייה ב־`received` או `in_progress`.
- **`/patient/new`:**
  - שדה טקסט: עד 2000 תווים, עם מונה.
  - שליחה מעבירה לפרטי הפנייה.
- **`/patient/requests/:id`:**
  - ציר מצב פשוט: התקבלה, בטיפול, ואז ממתינה למסמך / אצל צוות / הושלמה / נסגרה.
  - **`needs_document`:** ‏Alert מסוג warn עם בקשה מתוך התבנית `missing-document-v1`: "כדי להשלים את ההכנה חסרים המסמכים הבאים: …". לכל מסמך חסר יש טופס העלאה: סוג קובץ (pdf, jpg או png), ותוכן הקובץ.
  - **`completed`:** ‏Alert מסוג ok עם ההודעה שנמסרה.
  - **`in_review`:** ‏Alert מסוג info: "הפנייה הועברה לבדיקת צוות. לא נמסור מידע רפואי באופן אוטומטי."
  - **`closed`:** ‏"הפנייה נסגרה".
  - ריענון אוטומטי כל 3 שניות, כל עוד המצב לא סופי ולא ממתין למטופל.
- **הקובץ שמעלים:** הדמו לא מעביר קבצים בינאריים. המטופל בוחר קובץ, והלקוח קורא ממנו טקסט (`File.text()`) או משתמש בשם הקובץ, ושולח כ־`content`. אפשר גם להדביק את התוכן. ראו החלטה 3.

## 5. מסכי הצוות

- **`/staff`, "תור הסלמות":**
  - טבלה: מזהה פנייה (mono), מטופל, סוג הסלמה, ממצב, סיבות ועדכון אחרון.
  - ריענון כל 5 שניות.
  - לחיצה על שורה פותחת את הפנייה.
- **`/staff/cases/:id`:**
  - שלוש עמודות:
    1. **תוכן הפנייה:** פריטי ה־Data Log לפי סוג, עם כפתור "מחיקה לפי בקשת מטופל" (tombstone, עם אישור).
    2. **Audit:** ציר זמן, עם `.state` mono לכל מעבר.
    3. **הכרעה:** כפתורי ההחלטות המותרות, סיבה (חובה), והשדות הנדרשים לפי `required_fields`: `verified_identity_ref`, או `patient_deadline` כ־datetime-local.
  - ההכרעה נשלחת עם `shown_context_ref` של ההקשר שמוצג.
  - תשובת 409 `context_changed` מציגה Alert ו"רענון הקשר".
  - תשובה מוצלחת מחזירה לתור ומציגה הודעה.
- **`/staff/monitor`:** כל הפניות, עם סינון State ופרטים ו־Audit לכל פנייה. זה ה־Case Monitor, מאחורי אימות.
- **תווית "מה מותר מהמסך הזה":** מופיעה בצד המסך, כמו ב־`admin-login.html`.

## 6. נגישות ו־RTL

- `<html lang="he" dir="rtl">`, ו־CSS עם properties לוגיים בלבד, כמו בעיצוב.
- ‏focus-visible, ‏`aria-live` להודעות, ו־`aria-invalid` ו־`aria-describedby` לשגיאות בשדות.
- מתג מצב כהה ובהיר, שנשמר ב־`localStorage`.

## 7. החלטות (אוטונומיות)

1. **Vite ו־React TS בלי ספריית UI:** העיצוב מגדיר את כל הקומפוננטות.
2. **כניסה עם מזהה וסיסמה** במקום טלפון ו־OTP, בפריסה ובטקסטים של העיצוב. כפתורי משתמשי הדמו מקלים על הדגמה.
3. **העלאת מסמך כתוכן טקסטואלי:** ה־API של תת־פרויקט 5 מקבל `content` כמחרוזת, ה־Data Log שומר טקסט, והסיווג רץ על טקסט. קבצים בינאריים ו־OCR מחוץ לדמו.
4. **ריענון בסקירה (polling)** במקום WebSocket.
5. **שירות `frontend` ב־compose**, במצב dev, על פורט 5173, עם proxy ל־backend.
6. **קומפוננטות שלא הופיעו בעיצוב** (טבלה, StatusPill, ציר זמן, תפריט עליון): נבנות מאותם tokens (surfaces, lines, radii, ‏`.state` mono), באותה שפה ויזואלית.
